### User Story 1
As a driver, I want to create an account and maintain a basic profile so that I can use HITCHD to publish and manage shared journeys.

**Acceptance Criteria**:
- **Account creation**: User can create a HITCHD account.
- **Authentication**: User can securely authenticate to access their account.
- **Profile information**: User can maintain their basic profile information.
- **Account access**: Authenticated users can access the functionality available to their account.

**Priority**: MVP

### User Story 2
As a driver, I want to publish a journey with available seats and a requested contribution so that passengers travelling in the same direction can request to share my journey.

**Acceptance Criteria**:
- **Origin**: Driver can specify the journey origin.
- **Destination**: Driver can specify the journey destination.
- **Departure time**: Driver can specify the planned departure time.
- **Available seats**: Driver can specify the number of available seats.
- **Contribution**: Driver can specify the requested contribution toward shared travel costs.
- **Ride listing**: Driver can publish the journey so that it becomes available for passengers to search.

**Priority**: MVP

### User Story 3
As a passenger travelling to work, university, or another destination, I want to search for available journeys using my journey details and departure preferences so that I can find a suitable shared ride.

**Acceptance Criteria**:
- **Journey details**: Passenger can enter relevant journey details for their search.
- **Departure preferences**: Passenger can specify their preferred departure requirements.
- **Available rides**: System displays available journeys that match the passenger's search criteria.
- **Journey information**: Search results provide enough information for the passenger to identify potentially suitable journeys.

**Priority**: MVP

### User Story 4
As a passenger, I want to view the details of an available journey so that I can compare suitable rides before requesting a seat.

**Acceptance Criteria**:
- **Journey route**: Passenger can view the origin and destination of the journey.
- **Departure time**: Passenger can view the planned departure time.
- **Available seats**: Passenger can view the number of available seats.
- **Contribution**: Passenger can view the requested contribution toward shared travel costs.
- **Driver information**: Passenger can access relevant driver profile information.
- **Ride selection**: Passenger can identify a journey that is suitable for their travel needs.

**Priority**: MVP

### User Story 5
As a passenger, I want to request an available seat on a journey so that I can arrange a shared ride to my destination.

**Acceptance Criteria**:
- **Seat request**: Passenger can request an available seat on a listed journey.
- **Booking status**: The request is recorded with a pending booking status until it is accepted or declined.
- **Journey availability**: The system prevents requests when there are no available seats.
- **Booking visibility**: Passenger can view the status of their booking request.

**Priority**: MVP

### User Story 6
As a driver, I want to review and manage passenger booking requests so that I can decide which passengers can share my journey.

**Acceptance Criteria**:
- **Booking requests**: Driver can view requests received for a published journey.
- **Passenger information**: Driver can access relevant passenger profile information associated with a request.
- **Accept request**: Driver can accept a passenger booking request.
- **Decline request**: Driver can decline a passenger booking request.
- **Booking status**: The booking status is updated to reflect the driver's decision.

**Priority**: MVP

### User Story 7
As a user, I want to view and manage my bookings so that I can keep track of my shared journeys and their current status.

**Acceptance Criteria**:
- **Booking list**: User can view relevant bookings associated with their account.
- **Booking status**: User can see whether a booking is pending, confirmed, declined, or cancelled where applicable.
- **Booking details**: User can view relevant journey information associated with a booking.
- **Cancellation**: User can cancel an eligible booking.
- **Status update**: The booking status is updated when a cancellation occurs.

**Priority**: MVP

### User Story 8
As a passenger, I want to pay my agreed contribution through the application so that I can complete payment for a confirmed shared journey.

**Acceptance Criteria**:
- **Payment initiation**: Passenger can initiate payment for an applicable confirmed booking.
- **Payment provider**: Payment is processed through the integrated third-party payment provider.
- **Payment association**: The payment record is associated with the relevant booking.
- **Payment status**: The application records and displays the relevant payment status.
- **Payment failure**: The application can display when a payment attempt has failed.

**Priority**: MVP

### User Story 9
As a user, I want to view my booking and payment statuses so that I can clearly understand whether my shared journey and associated payment are confirmed.

**Acceptance Criteria**:
- **Booking status**: User can view the current booking status.
- **Payment status**: User can view the relevant payment status where a payment applies.
- **Status visibility**: Booking and payment statuses are presented clearly within the application.
- **Payment outcomes**: The system can represent relevant payment states including pending, successful, failed, or refunded where applicable.
- **Booking relationship**: Payment information is associated with the relevant booking.

**Priority**: MVP

### User Story 10
As a member of the HITCHD community, I want to report inappropriate behaviour so that I have a straightforward way to raise a trust or safety concern.

**Acceptance Criteria**:
- **Reporting mechanism**: User can report inappropriate behaviour through the application.
- **Report submission**: User can submit information relevant to the reported behaviour.
- **Associated information**: The report can be associated with the relevant user or journey where applicable.
- **Report visibility**: The application provides confirmation that the report has been submitted.
- **Safety information**: Relevant user and journey information is available to support basic trust and safety.

**Priority**: MVP
