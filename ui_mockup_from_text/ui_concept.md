# UI Concept - FAULT//INE

## Purpose

**Tagline:** ATTACK CHAINS DECODED

**Product-positioning line:** OFFSEC BUILT FOR DEVS

FAULTLINE provides an interactive visual representation of software vulnerabilities as connected nodes, revealing how individual weaknesses could combine into attack chains that lead to serious security breaches. Developers can explore each node to inspect vulnerable code, understand potential attack paths, and foresee how weaknesses could be exploited. By showing how remediation disrupts or breaks these chains, FAULTLINE empowers developers to proactively harden their software, mitigate risk and stay ahead in the ongoing cat-and-mouse game between attackers and defenders.

**What sets FAULTLINE apart:** FAULTLINE complements existing security tools by giving developers a dedicated, interactive way to uncover how vulnerabilities in their code could connect to form potential attack chains. Through a visual map of these relationships, developers gain the vantage point of an attacker — uncovering how weaknesses chain together, revealing potential attack paths, and understanding how attacks could unfold. This transforms security findings into actionable insight, helping developers make informed remediation decisions and break the chain before potential attacks become reality.

## Users

- Software Developers: identify and understand vulnerabilities in their code, uncover how weaknesses could combine into potential attack chains and make informed remediation decisions without requiring extensive offensive-security expertise.
- Security Professionals: investigate code vulnerabilities, analyse potential attack paths and support developers with security-focused remediation.

## Core Screens

- Dashboard: provides an overview of applications or projects being analysed, their security findings and identified potential attack chains that may require attention.
- AttackChain Discovery: provides an interactive, node-based visualisation of code vulnerabilities and their relationships. Users can select individual nodes to inspect vulnerable code, understand why it is vulnerable and uncover how weaknesses could connect into potential attack chains.
- AttackChain Attacks: visually traces potential attack paths, illustrating how connected vulnerabilities could combine to enable an attack and what the potential consequences could be. The visualisation updates as vulnerabilities are remediated, showing how code changes disrupt or break potential attack chains.
- Remediation: helps developers prioritise vulnerabilities based on their potential role in an attack chain and the impact of exploitation. It explains underlying code weaknesses and provides recommended fixes and relevant security references.

## Actions

- Select an application or project to review its code-security findings.
- Discover and explore visual relationships between identified vulnerabilities.
- Select individual nodes to inspect vulnerable code and understand why it is vulnerable.
- Uncover how weaknesses could chain together to create potential attack paths.
- Investigate how a potential attack could progress and what its consequences might be.
- Prioritise vulnerabilities according to their potential contribution to an attack chain and the impact of exploitation.
- Review recommended fixes and relevant security references to support remediation.
- See how addressing vulnerabilities changes, disrupts or breaks potential attack chains.
